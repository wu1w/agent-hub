# 2026-09-17 审计问题修复说明

对应原始报告：`../agent-hub-audit-2026-09-17.md`。本文件记录代码修复及使用变化，不替代真实客户端加载验收。后续三条回归及整体复核见 [第六轮修复审计](audit-round6-2026-09-17.md)。

## 数据和提交

- **A01**：无法映射回原条目、原字段的掩码拒绝保存，返回 409，密文及 revision 不变。保存前保留一份 `vault.bin.previous` 加密版本，权限 0600。掩码文稿中直接改名仍不支持；保留原 ID/字段名，或先显示并取得真实值后改名。不通过位置猜测秘密归属。
- **A02**：Cursor 先解码 JSONL；所有扫描器保留原始文本直到脱敏完成，再归一化和截断。脱敏同时识别原值、空白折叠值和 JSON 转义值。重建索引会清理现存索引中的已知秘密，并压缩 SQLite、清空 WAL；不会改写历史交接。Vault 不可用时中止且保留原文件。索引目录 0700，数据库及 WAL/SHM 0600。
- **A03**：从实际投递文件的最近存在父目录检查 Git，全局 dotfiles 和工作区使用同一保护。已跟踪文件拒绝写入，非跟踪文件写入本地 exclude。
- **A06**：HTTP Vault 正文、授权、目录投递和 Vault 专属响应在同一事务中；全局 snapshot 独立刷新，不影响提交结果。投递失败回滚原密文与授权，原 revision 可重试。CLI 授权的读取、修改与同步也在同一锁和事务内。
- **A07**：项目记忆创建使用 POST/create-only，禁止 global 保留名，已有项目返回 409。PUT 保留为明确的编辑操作。
- **A13**：Keychain 写入失败仅返回固定错误码，不传播含主密钥 argv 的底层错误消息。

## 挂载和编辑

- **A04**：摘链、排除目标、独立拷贝及删除扫描实际物理软链，包括嵌套别名；不会递归进入目录软链或受保护的厂商目录。`repair` 可将旧版残留的 Own→Hub 链转为独立副本。
- **A05**：targets 和正文共用当前编辑器草稿，调整范围会同时保存正文，界面已注明。保存带载入 revision；旧编辑器写回返回 409。提交期间防止交错操作。
- **A08**：通过 YAML AST 读取、更新 `hub.targets`，保留其他元数据，校验 Agent ID，正确引用 `*`。`repair` 只迁移旧 Hub 写出的空别名通配符，不宽泛容忍其他非法 YAML。
- **A09**：URL 解析进入请求错误边界，畸形请求返回 400，下一条请求仍可成功。
- **A10**：缺失工作区跳过投递并显示不可用，可按原登记路径注销；不阻止其他记忆更新，不重建已删除目录。
- **A11**：绑定提交时禁用控件，失败恢复原选项并显示错误，成功使用服务端 snapshot。
- **A12**：Hub 创建的空配置目录不再作为客户端存在证据；分别暴露目录、独立配置/会话、可执行命令及扩展证据。登录和真实消费始终标为待验证。

## 原生入口与交接

- **A14**：同一原生目标的不同项目作用域返回 409；同一作用域仍可同步更新。界面明确 Own 只停止 Hub 投递，不隔离其他客户端读取共享规则。没有宣称 HTML 区块构成权限边界，也没有宣称所有客户端已有独立入口。
- **A15**：交接前刷新来源索引。Cursor/Codex/Hyper 从最多 512 KB 的完整尾部 JSONL 记录获取最近请求/回复；缺失最近回复时明确提示。摘要标注为有界尾部，未生成或冒称整场总结、结构化 next_steps。
- Cursor 的 `open -R` 显示为“在 Finder 显示交接文件”，服务端直接显示文件，不再以启动 Agent 的终端流程包装。
- Ctx/Vault/Identity 的旁路文件显示配置及待验证状态；Vault 的显式按名调用不再暗示原生自动发现。真实原生接线仍须逐客户端新会话验收。

## 补充修复

- Identity、SOUL、子代理草稿独立于卡片 DOM 保存，切换子代理或刷新卡片后保留；保存带原 revision，离开页面有未保存提示。
- AGENTS.md 保存绑定载入时的工作区与 revision，输入框变更不会重定向保存；重新载入前提示未保存草稿。
- Vault 增加“标记秘密字段”动作，随文稿提交 secretFields。
- CLI 只消费 Hub 自己的 `--`，子命令后续分隔符原样传递；并发增量授权不会覆盖彼此。

## 升级与验证

重新启动项目服务后生效。需要修复已有派生状态时，可在对应 Hub 环境执行：

```sh
npm run hub -- repair
npm run hub -- index
```

`repair` 可能修正旧 YAML、软链和 Own 独立副本；`index` 仅重建派生索引。需要清理历史交接中的当前已知秘密时，显式执行 `npm run hub -- scrub-handoffs`；此命令事务化处理交接文件，Vault 不可用时拒绝执行。未在本次开发中对个人 Hub 执行这些维护命令。已轮换或从 Vault 删除的历史秘密无法仅凭当前 Vault 识别；如需清理此类历史派生资料，应删除对应旧交接并重新生成，不能把本次脱敏视为历史泄漏取证结论。
